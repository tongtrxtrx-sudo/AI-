# 多层合并与海外折算 Demo 独立只读复核记录

复核日期：2026-10-20。复核对象：`epm-demo-multilevel` 的新计算、领域、HTTP、界面和打包流程。产品源代码由各模块负责人维护；本复核仅使用内存副本和自行创建的临时账套，未修改产品源码或共享验收数据。

本复核已经执行的范围内，未留下未解决的计算、事务或USD逐月抵销阻断。下文区分独立执行的检查和负责人后续修复后的验证范围，不能用本记录替代最终候选包的完整浏览器及 Windows 验收证据。结案时已收到最终候选冻结通知。

## 1. 实际执行并通过的检查

### 严格分级计算与完整三表

独立调用正式计算函数，按鸿旺小合并、海外小合并、集团的顺序建立有效已签核子结果，再计算上级；没有使用 preview 代替正式上卷。1—12期三个层级的期初平衡、期末平衡、现金流勾稽及权益滚动均通过。

9期实际结果如下，金额为本结果报表币种的万元：

|结果|报表币种|营业收入|净利润|资产|外币报表折算差额|现金汇率影响|
|---|---|---:|---:|---:|---:|---:|
|鸿旺小合并|人民币|1,400|450|650|0|0|
|海外小合并|美元|100|20|200|0|0|
|杭州天元集团合并|人民币|2,650|770|2,370|74|90|

集团直接输入包含鸿旺及海外的结果编号、版本和签核状态；下级抵销来源随结果继承。集团长期股权投资抵销后为0，实收资本为950，留存收益为770。鸿旺管理合并关系没有被当作鸿旺对两家独立法人的法律持股关系。

仅将期末汇率7.2改成7.3，集团利润仍770，资产变为2,390，折算差额变为86，现金汇率影响变为110。海外组件本身对应净利润140人民币万元保持不变，验证了期末余额、各月损益和现金汇率影响使用不同规则。

### 来源、历史权益和错误配置拒绝

独立构造以下输入，并确认正式计算拒绝：

- 子结果缺失、预览、失效、未签核、期间或币种不符、校验失败。
- 子源报送已换版而仍引用旧子结果。
- 合并树存在重复法人、重复成员、循环、未知成员或CNY→USD输入。
- 下级已处理来源标识在上层再次抵销，或内部销售放在非最低共同合并层。
- 合法同步改动子公司资本、现金及其历史资本明细后，仍沿用原投资资本抵销金额。
- 合法同步改动天元母公司投资、资本及历史资本明细后，仍沿用原950抵销。
- 改资本历史汇率后，投资账面与逐公司历史资本抵销不一致。
- 将投资抵销的真实母公司伪造成鸿旺。

上述错误没有通过利润或CTA补差被自动修平。历史权益测试另由计算模块测试覆盖：期初已确认人民币留存收益加逐月折算利润，不按期末汇率重算整行。

独立运行 `python -m unittest test_consolidation -v`，当时22项测试全部通过，包含两个月采用不同平均汇率、USD内部销售按实际月份抵销、月度与累计一致性、历史留存、当前汇率版本选择及内容被改动的快照拒绝。

### 领域状态与真实 HTTP / SQLite

独立启动真实HTTP服务和新的SQLite账套，完成以下操作：

1. 首次启动获得正式初始化签核结果，集团收入2,650。
2. 验证启动凭证、Cookie会话、Origin、CSRF限制，旧revision返回409。
3. 重开鸿旺使鸿旺及集团失效，海外兄弟结果仍有效；旧结果无法重新签核，集团不能绕过子结果先计算。
4. 给鸿旺猫爬架法人同步补记现金销售9，保存完整源版本，重新计算和签核鸿旺，再上卷集团，收入为2,659、净利润为779。
5. 原集团历史结果的财务报告内容保持原值。
6. 独立启用新分类汇率版本后，仅实际依赖外币转换的集团结果失效；鸿旺人民币和海外美元原币结果保持有效。
7. 不平衡源报送整体回滚，revision不增长；审计只读角色的写入被403拒绝。
8. 旧版journal、signoff、rate_save、checks_run等财务动作被拒绝，未形成绕过新结果体系的成功假保存。
9. 关闭服务后，用同数据目录建立新服务，当前结果逐字段一致，验证持久化而非浏览器缓存。

### 独立 Chromium 检查

通过真实API在私有账套中保存含HTML标记及事件属性的单元名、源文件名、公司名、经营说明，再打开21项菜单及结果详情。界面正常渲染，没有执行注入脚本，也没有页面JavaScript错误。切换海外小合并后，币种控件锁为USD，经营分析明确拒绝把该口径直接与集团CNY预算比较。

随后独立执行USD专项：在2期账套中，海外甲1月新增内部销售4、2月新增5，海外乙同步记录对应成本；分类平均及现金流汇率分别设1月8、2月6。通过实际界面选择逐月发生、录入4与5、保存草稿、审批、计算并签核海外小合并，再通过真实HTTP正式上卷。海外收入按各月已抵销结果11.12×8＋11.10×6＝155.56人民币万元，符合预期，没有把累计9全部落在2月。通过界面重开海外、填写原因并停用该抵销后，集团结果失效、原海外结果report内容不变、停用事项不再显示审批操作。该专项已独立执行通过。

## 2. 复核中发现并反馈的问题

|问题|影响|处理情况|
|---|---|---|
|领域依赖fingerprint覆盖纯计算快照fingerprint|新账套初始化根合并失败|后端分为inputFingerprint与快照内容fingerprint；独立真实HTTP重启及上卷复测通过。|
|USD累计抵销全部记到当前月|月平均汇率不同会发生折算错期|计算器要求完整monthlyEffects；后端支持monthlyAmounts；22项计算测试中相应回归通过；独立真实界面专项4/5、汇率8/6、折算155.56也通过。|
|改变OS单元报表币种后，历史USD结果反向覆盖CNY操作上下文|下一次计算被币种校验拒绝；简单改上下文还会错误标注历史金额单位|已向界面及后端负责人提供复现。界面负责人分离操作币种与历史展示币种，并报告真实浏览器路径通过；该最终界面修复未由本独立复核再次执行，最终以界面及QA验收记录为准。|
|误建抵销草稿缺少撤销路径|用户试验后难以恢复原配置|后端和界面增加停用、原因、级联失效及历史保留；独立真实界面停用专项已通过。|

最终界面补丁复验期间，执行环境曾发生 `exec-server transport disconnected`；环境恢复后已补完USD逐月与停用专项。本复核没有把中断的命令记为通过，也没有将环境中断算作产品失败。单元自身修改币种后的最终操作路径由界面负责人及最终QA覆盖，本复核未重复启动该项浏览器流程。

## 3. 打包流程只读检查

已检查Windows构建、材料刷新、ZIP打包和原生集成测试脚本：当前后端各Python文件、前端HTML、启动器及EXE的哈希与测试证据建立关联；材料刷新和最终打包会拒绝运行字节不匹配的旧证据；数据库、日志、启动凭证文件等不能进入软件包。该检查是代码审查，最终EXE实际运行结论应读取Windows原生集成证据。本复核没有另行声称在实体Windows电脑上运行过软件。

## 4. 本轮研发边界

本轮确认案例为三家互不重叠独立法人组成鸿旺管理小合并、全USD海外小合并、再上卷人民币集团。采用全资、无本期资本变动、无分红、无收购差额的演示模型。公开API使用统一资本历史汇率；抵销已核对子公司实报资本及母公司投资总额，但尚不是按每家被投资法人独立维护的原始投资明细账。该独立历史投资台账、复杂股权变动、商誉、少数股东等应在正式研发阶段另建模型，不属于本轮确认案例的阻断。
